# Deployment Guide

This guide covers deploying the Read It Later application to production.

## Overview

- **Backend + Database**: Railway
- **Web Frontend**: Vercel
- **Mobile Apps**: Expo EAS Build → App Stores

## Prerequisites

- Railway account (free tier available)
- Vercel account (free tier available)
- Expo account (for mobile builds)
- GitHub repository

## Backend Deployment (Railway)

### 1. Create Railway Project

1. Go to [Railway.app](https://railway.app)
2. Click "New Project"
3. Select "Deploy from GitHub repo"
4. Choose your repository
5. Railway will auto-detect Node.js and deploy

### 2. Add PostgreSQL Database

1. In your Railway project, click "+ New"
2. Select "Database" → "PostgreSQL"
3. Railway creates a database and provides connection URL

### 3. Configure Environment Variables

In Railway project settings, add these environment variables:

```env
# Auto-generated by Railway
DATABASE_URL=postgresql://...

# Required
NODE_ENV=production
JWT_SECRET=<generate-secure-random-string>
JWT_EXPIRES_IN=7d
PORT=3000

# CORS (add your Vercel domain)
CORS_ORIGINS=https://your-app.vercel.app,https://www.your-app.com

# Optional: OAuth
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GOOGLE_CALLBACK_URL=https://your-api.railway.app/api/auth/google/callback

# Web app URL (for OAuth redirects)
WEB_URL=https://your-app.vercel.app
```

### 4. Deploy Backend

Railway automatically deploys on every push to main branch.

**Manual Deploy:**
```bash
# Install Railway CLI
npm i -g @railway/cli

# Login
railway login

# Link project
railway link

# Deploy
railway up
```

### 5. Run Database Migrations

In Railway project:

1. Go to your backend service
2. Click "Settings" → "Deploy"
3. Set deploy command to: `npx prisma migrate deploy && npm start`

Or use Railway CLI:
```bash
railway run npx prisma migrate deploy
```

### 6. Verify Deployment

Check your backend is running:
```
https://your-backend.railway.app/health
```

Should return:
```json
{"status":"ok","timestamp":"..."}
```

## Web Frontend Deployment (Vercel)

### 1. Create Vercel Project

1. Go to [Vercel](https://vercel.com)
2. Click "Add New" → "Project"
3. Import your GitHub repository
4. Configure:
   - **Framework Preset**: Vite
   - **Root Directory**: `web`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`

### 2. Configure Environment Variables

In Vercel project settings → Environment Variables:

```env
VITE_API_URL=https://your-backend.railway.app
```

### 3. Deploy

Vercel automatically deploys on every push to main branch.

**Manual Deploy:**
```bash
# Install Vercel CLI
npm i -g vercel

# Deploy
cd web
vercel
```

### 4. Configure Custom Domain (Optional)

1. Go to Vercel project settings → Domains
2. Add your custom domain
3. Update DNS records as instructed
4. Update CORS_ORIGINS in Railway to include new domain

### 5. Verify Deployment

Visit your Vercel URL and test:
- Registration
- Login
- Saving links
- Reader mode

## Mobile Deployment

### iOS and Android

#### 1. Install EAS CLI

```bash
npm install -g eas-cli
```

#### 2. Configure Expo

```bash
cd mobile
eas login
eas build:configure
```

This creates `eas.json`:

```json
{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}
```

#### 3. Update API URL

Edit `mobile/src/services/api.ts`:

```typescript
const API_URL = 'https://your-backend.railway.app';
```

#### 4. Build for iOS

```bash
eas build --platform ios
```

For App Store distribution, you'll need:
- Apple Developer Account ($99/year)
- App Store Connect app created
- Provisioning profiles and certificates

#### 5. Build for Android

```bash
eas build --platform android
```

For Play Store distribution, you'll need:
- Google Play Console account ($25 one-time)
- App created in Play Console
- Signed APK/AAB

#### 6. Submit to App Stores

**iOS:**
```bash
eas submit --platform ios
```

**Android:**
```bash
eas submit --platform android
```

#### 7. Internal Testing (Recommended First)

**iOS TestFlight:**
```bash
eas build --platform ios --profile preview
```

**Android Internal Testing:**
Upload APK to Play Console Internal Testing track.

## Post-Deployment

### 1. Update OAuth Callback URLs

If using Google OAuth:

1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Update authorized redirect URIs:
   - `https://your-backend.railway.app/api/auth/google/callback`
3. Update authorized JavaScript origins:
   - `https://your-app.vercel.app`

### 2. Security Checklist

- [ ] Change all default passwords
- [ ] Generate strong JWT_SECRET
- [ ] Configure CORS properly
- [ ] Enable HTTPS only
- [ ] Review database security rules
- [ ] Set up monitoring and alerts
- [ ] Configure rate limiting (recommended)
- [ ] Enable Vercel/Railway security features

### 3. Monitoring Setup

**Railway:**
- Enable metrics in project settings
- Set up notification webhooks

**Vercel:**
- Enable Web Analytics
- Set up deployment notifications

**External:**
- [Sentry](https://sentry.io) for error tracking
- [UptimeRobot](https://uptimerobot.com) for uptime monitoring

### 4. Backup Strategy

**Database:**
- Railway provides automatic daily backups
- Set up manual backup schedule:
  ```bash
  # Using Railway CLI
  railway run pg_dump $DATABASE_URL > backup.sql
  ```

**Code:**
- Always in Git/GitHub
- Tag releases: `git tag v1.0.0`

## Continuous Deployment

### GitHub Actions (Optional)

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: 18
      - run: npm install
      - run: npm run build

  deploy-backend:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Deploy to Railway
        run: |
          # Railway auto-deploys on push
          echo "Backend deployed via Railway"

  deploy-web:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Deploy to Vercel
        run: |
          # Vercel auto-deploys on push
          echo "Web deployed via Vercel"
```

## Scaling Considerations

### Backend (Railway)

Railway plans:
- **Free**: $5 credit/month, auto-scaling
- **Pro**: $20/month, higher limits
- **Team**: Custom pricing

To scale:
1. Upgrade Railway plan
2. Enable auto-scaling in service settings
3. Monitor memory and CPU usage

### Database (Railway)

Railway PostgreSQL:
- Starts small, scales on demand
- Consider migrating to dedicated Postgres (Neon, Supabase) for larger apps

### Web (Vercel)

Vercel automatically scales:
- Edge network CDN
- Serverless functions
- No manual intervention needed

## Troubleshooting

### Backend Won't Deploy

1. Check Railway logs
2. Verify environment variables
3. Test build locally: `npm run build`
4. Check Node.js version matches

### Database Migration Fails

```bash
# Reset and re-run
railway run npx prisma migrate reset
railway run npx prisma migrate deploy
```

### Web App Can't Connect to API

1. Check VITE_API_URL is correct
2. Verify CORS settings in backend
3. Check Railway backend is running
4. Test API health endpoint

### Mobile Build Fails

1. Check `eas.json` configuration
2. Verify all native dependencies are compatible
3. Check Expo SDK version
4. Review EAS build logs
